3.5 Asynchronous JS & Fetch API (`async/await`)

Mengambil data dari Server REST API secara asinkron tanpa memuat ulang (reload) seluruh halaman web.

Yang Akan Anda Pelajari:
  • ✓ Siklus hidup Asynchronous dan Promise
  • ✓ Pola penulisan async/await yang bersih
  • ✓ Penanganan error jaringan dengan blok try/catch
  • ✓ Pengecekan respon HTTP response.ok sebelum parsing JSON

Dunia web modern bekerja secara asinkron (non-blocking asynchronous). Ketika aplikasi Anda mengirim request ke server eksternal, antarmuka pengguna tidak boleh macet atau membeku saat menunggu respon jaringan. Pola async/await membuat penulisan kode asynchronous sejelas dan sebersih kode sinkron biasa.

Pola Standar Industri: `async/await` + `try/catch`

JavaScript — Fetch Pattern 
const fetchUserData = async (username) => {
  try {
    const response = await fetch(`https://api.github.com/users/${username}`);
    
    // Periksa status HTTP 200 OK
    if (!response.ok) {
      throw new Error(`HTTP Error status: ${response.status}`);
    }

    const data = await response.json();
    console.log("Data user:", data);
    return data;
  } catch (error) {
    console.error("Gagal mengambil data dari server:", error.message);
  }
};

💡 Selalu Cek `response.ok`

Fetch API tidak akan mereject Promise hanya karena server mengembalikan error 404 Not Found atau 500 Server Error. Promise hanya reject jika terjadi kegagalan jaringan fisik (offline/CORS blocked). Oleh karena itu, selalu uji if (!response.ok) sebelum menguraikan JSON.

Quick Check (+50 XP) Uji Pemahaman

Apakah Fetch API otomatis mereject Promise saat server merespon dengan status 404 Not Found?

Penjelasan: Fetch API hanya mereject jika terjadi kegagalan jaringan fisik (offline/DNS). Status 404/500 tetap resolve sehingga response.ok wajib diuji.
