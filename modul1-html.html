🧱 Modul 1: Semantik & Aksesibilitas HTML5 (Edisi Lengkap)

Pelajari anatomi kode HTML yang dicintai oleh Mesin Pencari (Google), dipahami oleh Screen Reader, dan berkinerja tinggi (Core Web Vitals).

1.1 Struktur Semantik & Hierarki SEO

Membangun website dengan <div> untuk segala hal (*Div Soup*) adalah kesalahan pemula terbesar. Robot perayap mesin pencari (seperti Googlebot) tidak memiliki mata. Mereka membaca struktur kode untuk memahami mana yang merupakan judul utama, mana yang konten pendukung, dan mana yang sekadar menu navigasi.

Elemen Struktural Wajib HTML5:

  • <header>: Kepala dokumen atau area navigasi atas (berisi logo & menu).
  • <main>: Aturan emas: Hanya boleh ada SATU tag main dalam satu halaman. Ini adalah jantung konten web Anda.
  • <article>: Konten independen yang masuk akal jika dibaca terpisah (misal: postingan blog, kartu produk).
  • <aside>: Konten sekunder yang berada di luar topik utama (misal: sidebar, rekomendasi artikel, iklan).
  • <figure> & <figcaption>: Pembungkus untuk media (gambar/grafik) yang memiliki teks keterangan.
❌ Bad Practice (Sulit dibaca Mesin Pencari)
<div class="header-utama">...</div>
<div class="konten-tengah">
  <div class="postingan">...</div>
  <div class="sidebar-kanan">...</div>
</div>
<div class="footer-bawah">...</div>
✅ Good Practice (Industry Standard Semantic)
<header>
  <nav>
    <!-- Menu Navigasi -->
  </nav>
</header>

<main>
  <article>
    <header>
      <h1>Judul Artikel Utama</h1>
      <p>Ditulis pada <time datetime="2026-10-15">15 Oktober 2026</time></p>
    </header>
    
    <section>
      <h2>Bab Pendahuluan</h2>
      <p>Isi konten...</p>
      
      <figure>
        <img src="grafik.jpg" alt="Grafik peningkatan pengguna">
        <figcaption>Gambar 1.1: Lonjakan pengguna kuartal 3.</figcaption>
      </figure>
    </section>
  </article>

  <aside>
    <h3>Artikel Terkait</h3>
    <!-- Link artikel lain -->
  </aside>
</main>

<footer>
  <p>© 2026 Hak Cipta Dilindungi.</p>
</footer>

1.2 Aksesibilitas (a11y) & ARIA Attributes

Website profesional harus mematuhi standar WCAG (Web Content Accessibility Guidelines). Ini memastikan website dapat digunakan oleh penyandang disabilitas penglihatan menggunakan Screen Reader (seperti NVDA atau VoiceOver) dan pengguna yang bernavigasi khusus menggunakan keyboard.

Prinsip ARIA (Accessible Rich Internet Applications):

  • aria-label: Digunakan untuk memberi nama pada elemen yang tidak memiliki teks terlihat. (Contoh: Tombol 'X' untuk menutup modal).
  • aria-hidden="true": Menyembunyikan elemen dekoratif murni dari Screen Reader agar tidak menimbulkan suara bising yang tidak perlu (misal: ikon hiasan).
  • aria-expanded: Memberitahu Screen Reader apakah sebuah menu dropdown sedang terbuka ("true") atau tertutup ("false").
<!-- 1. Tombol Ikon Tanpa Teks -->
<!-- Jika tidak ada aria-label, pembaca layar hanya akan membacanya sebagai "Tombol" yang membingungkan. -->
<button aria-label="Tutup Jendela Konfirmasi" class="btn-close">
  <svg aria-hidden="true">...ikon X...</svg>
</button>

<!-- 2. Menu Dropdown Interaktif -->
<button aria-expanded="false" aria-controls="menu-list">
  Pengaturan Profil
</button>
<ul id="menu-list" hidden>
  <li><a href="#">Ubah Password</a></li>
</ul>

<!-- 3. Manajemen Gambar (Alt Text) -->
<img src="data-penting.jpg" alt="Grafik batang menunjukkan kenaikan laba 20%">
<img src="garis-hiasan.png" alt="" aria-hidden="true"> <!-- Dekorasi murni -->

1.3 Form & Validasi Bawaan Lanjutan

HTML5 sangat kuat. Anda seringkali tidak membutuhkan JavaScript rumit hanya untuk memvalidasi formulir sederhana. Manfaatkan atribut validasi asli browser yang lebih ringan dan aman.

Atribut Validasi Penting:

  • required: Input tidak boleh kosong.
  • pattern="[regex]": Mencocokkan teks dengan aturan Regular Expression (contoh: huruf besar saja, format plat nomor, dll).
  • minlength & maxlength: Membatasi jumlah karakter.
  • <datalist>: Membuat input teks yang memiliki opsi auto-complete/saran otomatis bawaan browser.

1.4 Optimasi Media & Mencegah CLS (Core Web Vitals)

Google memberi peringkat lebih tinggi pada website yang memuat dengan cepat. Gambar adalah penyumbang ukuran *bandwidth* terbesar. Standar industri modern menggunakan tag <picture> dan teknik Lazy Loading.

Aturan Wajib Optimasi Gambar:

  1. Selalu definisikan width dan height: Ini mencegah masalah Cumulative Layout Shift (CLS), di mana teks terdorong ke bawah secara tiba-tiba saat gambar selesai dimuat.
  2. Format Modern: Gunakan format .webp atau .avif yang ukurannya 50% lebih kecil dari JPG dengan kualitas yang sama.
  3. Lazy Loading: Tambahkan loading="lazy" agar gambar di bagian bawah halaman tidak didownload sebelum pengguna men-scroll ke sana.
<!-- Tag Picture memungkinkan kita menyajikan format terbaik -->
<!-- Browser akan membaca dari atas. Jika mendukung AVIF, ia pakai AVIF. 
     Jika tidak, ia turun ke WebP. Jika tidak lagi, ia turun ke JPG asli. -->
<picture>
  <source srcset="banner-promo.avif" type="image/avif">
  <source srcset="banner-promo.webp" type="image/webp">
  <img 
    src="banner-promo.jpg" 
    alt="Diskon akhir tahun 50%" 
    width="1200" 
    height="600" 
    loading="lazy"
    decoding="async">
</picture>

1.5 Open Graph & Social Meta Tags

Pernahkah Anda membagikan URL di WhatsApp, LinkedIn, atau Twitter, dan tiba-tiba muncul kartu pratinjau yang indah dengan gambar, judul, dan deskripsi? Itu bukanlah sihir, melainkan protokol Open Graph (OG) dan Twitter Cards.

Data ini diletakkan di dalam tag <head> dokumen Anda.

<head>
  <!-- Pengaturan Warna Tema Browser (Mobile) -->
  <meta name="theme-color" content="#2563eb">

  <!-- Open Graph Basic (Facebook, WA, LinkedIn) -->
  <meta property="og:type" content="website">
  <meta property="og:url" content="https://portofoliokamu.com/">
  <meta property="og:title" content="Portofolio Web Developer | Raihan">
  <meta property="og:description" content="Kumpulan proyek web modern berbasis React dan Laravel.">
  <!-- Gambar OG idealnya berukuran 1200 x 630 piksel -->
  <meta property="og:image" content="https://portofoliokamu.com/assets/og-cover.jpg">

  <!-- Twitter Card Khusus -->
  <meta name="twitter:card" content="summary_large_image">
</head>

1.6 Data Attributes (`data-*`) & Custom State

HTML5 memperbolehkan kita membuat atribut kustom asalkan diawali dengan kata data-. Teknik ini sangat lazim di industri untuk menyimpan data "tersembunyi" di dalam tag HTML tanpa mengacaukan struktur atau tampilan, yang nantinya akan diproses oleh CSS atau JavaScript.

<!-- HTML: Menyimpan status ketersediaan barang dan ID Database -->
<div class="product-card" data-product-id="A883" data-stock="habis">
  <h3>Sepatu Sneaker Pro</h3>
</div>
/* CSS: Kita bisa mengubah gaya (styling) berdasarkan data attribute! */
.product-card[data-stock="habis"] {
  opacity: 0.5;
  pointer-events: none; /* Menonaktifkan klik */
}

/* Menambahkan teks otomatis dari data attribute menggunakan pseudo-element */
.product-card[data-stock="habis"]::after {
  content: " STOK KOSONG";
  color: red;
  font-weight: bold;
}
// Javascript: Mengambil nilai data attribute
const card = document.querySelector('.product-card');

// "data-product-id" otomatis dikonversi menjadi camelCase di JS
console.log(card.dataset.productId); // Output: "A883"
console.log(card.dataset.stock);     // Output: "habis"
